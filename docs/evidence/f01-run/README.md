# F01-RUN and F01-HUD-ROOM evidence

Window captures (640x360, the debug build under xvfb, no audio, no recording) of the floor run of `--scene f01_late --f01-run` and of the room HUD. The behaviour is documented in [`docs/03-tech/floor01-scene.md`](../../03-tech/floor01-scene.md#the-floor-run-f01-run-and-the-room-hud-f01-hud-room) and the owner instructions are in [the playtest packet](../f01-playtest/README.md).

| `hud-room-hoarder-run-start.png` | `--scene f01_late --f01-run --f01-room hoarder --room-pilot hoarder --capture-sequence 600:900:2` (frame 0, tick 600) | a run entered at room 1, the Hoarder (since CORRAL-F the first listed room is room 0, the corral: a bare `--f01-run` starts there and refuses the `hoarder` pilot, so the command names `--f01-room hoarder`); the strip reads `THE HOARDER · TRY 1` and shows no TEST LOADOUT tag (the run's own start state) |
| `room-clear-panel-hoarder.png` | the same run, frame 1 (the exit tick, 1385) | the facts-only room-clear panel, `ROOM 2/8 CLEARED: THE HOARDER` (recaptured on the CORRAL-F head; the earlier capture read `ROOM 1/5`, when the Hoarder was the first of five listed rooms): ticks and clock, deaths, restarts, the dynamite granted in the room, the run so far, the next room with the carried ledger, the recording state; no score, no rating |
| `hud-room-boiler-test-loadout.png` | `--scene f01_late --f01-room boiler --f01-loadout all --room-pilot direct --capture-sequence 300:100:1` | a room launched on its own under the `all` loadout: `GOBLIN BOILER · TRY 1` and the TEST LOADOUT tag (PT-SCENE U5; the tag shows under `all` only) |

**Capture note.** A `--capture-sequence` pre-simulates the room to the requested tick before the window draws it, and the combat clock (`CombatState::elapsed`, ticks over every attempt) keeps counting after the exit, so the panel of this capture reads 1500 ticks for an exit reached on tick 1385. In live play the panel opens on the exit tick itself (`F01_RUN_ROOM_CLEARED room=hoarder ticks=1385` in a timed window run of the same pilot). A scripted run shows the panel but never relaunches.

**A real relaunch** ([`live_relaunch.txt`](live_relaunch.txt)): a live window run of `--scene f01_late --f01-run --f01-room boiler` under xvfb, driven by synthetic keys (xdotool: D held, Space and J tapped, Return on the panel, Esc in the next room). The Boiler's exit is reached on tick 943, the panel opens (`F01_RUN_ROOM_CLEARED`), Return relaunches (`F01_RUN_RELAUNCH room=hazards`), the Boiler's PLAYTRACE session is saved as completed before the `exec`, the same process starts the hazard room (`F01_LATE_ENTRY room=hazards`) with the Boiler's ledger in its descriptor (`f01_carry`: the dynamite and the jump boost held; no receipt, because this run started at the Boiler), and both sessions verify strict in a fresh process (`playtrace verify`: `PASS scope=full`). This is a scripted key sequence, not a human playing. The floor-end panel and the Hoarder's carried receipt are covered by unit tests (`f01_run::tests::an_exit_relaunches_into_the_next_room_or_ends_the_floor`, `the_hoarders_dynamite_survives_every_listed_room_of_the_run`, `a_carried_floor_run_room_verifies_strict_from_its_descriptor`), not by a window run. **NOT RUN:** a human-played run through all five rooms, on a pad or on real hardware. Game feel is the owner's call.
