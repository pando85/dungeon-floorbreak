# PLAYTEST-READY-01 evidence

Outputs of the full local check list and the whole-run smoke that stand behind [the owner's playtest packet](../../04-production/f01-playtest-ready-01.md). Debug build, xvfb, no GPU, no human; nothing here is game feel and nothing is accepted.

| File | What it holds |
| --- | --- |
| [`checks.txt`](checks.txt) | One block per check of the local list on the final head: `cargo fmt`, `cargo clippy -D warnings`, `cargo test --all-targets`, `check_docs.py`, `ci_floor01_combat.sh headless` and `render`, `check_f01_owner_commands.sh`, `validate_assets.py`, the art, pixel-art and cost-report unit tests, and two `export_assets.sh` runs with the tree left clean, each with its exit status and summary lines. |
| [`run_smoke.txt`](run_smoke.txt) | `scripts/f01_run_smoke.sh`: one headless `--scene f01_late --f01-room ID` launch per manifest row in run order (17 rooms), each with its entry line, `*_SMOKE_OK` marker and combat state hash. |
| [`carried_run_chain.txt`](carried_run_chain.txt) | The ignored `print_the_carried_run_chain` helper of `src/f01_run.rs`: the ledger carried into, and handed on by, each of the 17 rooms through the relaunch argument. |
| [`SHA256SUMS`](SHA256SUMS) | Checksums of the files above. |

**What the whole-run smoke proves, and what it does not.** `--scene f01_late --f01-run` relaunches the binary once per room, and a piloted run cannot cross a room boundary (ROOM-PILOT-RUN, an open follow-up), so there is no scripted player that walks all 17 rooms in one process. The evidence instead has three parts: (1) `run_smoke.txt` launches each of the 17 manifest rows headless in run order and reads its entry line and smoke marker; (2) `carried_run_chain.txt` walks the carried ledger through the 17 rooms (the camp and the aftermath are walked to their exit first; the other rooms are read at their start through the shared constructors, so the refuge's boost and the guild's biscuit, earned inside those rooms, show up only through the later pins and the fixtures that cover them); (3) the `f01_run` unit tests (`cargo test f01_run`, inside the full test run) cover the order, the relaunch argument, the room-clear and floor-end panels, and that the Hoarder's dynamite survives every listed room. `check_f01_owner_commands.sh` starts the real window on the first room of `--f01-run`, in the middle of the floor and in every room with every pilot flag the packet names. **NOT RUN:** a human or scripted crossing of a real room exit into the next room's window, a real two-pad session, a release build, and `tools/record-run.sh`.
