# Agent work order: CARL-PROG-01 (Carl's Floor 01 combat progression)

**Status:** design adopted (CP-Q01..CP-Q43, top-tier design under the owner's design-defaults directive, 2026-11-21); not implemented. The design PR changes no runtime source, art source, atlas, controller binding, tuning table or authoritative simulation. The [spec](../03-tech/carl-prog-01-floor01-combat-progression.md) holds every adopted value; this work order splits delivery into small PRs with disjoint file ownership.

**Goal:** Carl earns two permanent, story-event-driven capabilities on Floor 01: a thrown timed charge on Circle/B after the Hoarder (dynamite) and reinforced punches after the Juicer (gauntlet), both checkpoint-safe, both data-driven and both invisible to every existing golden unless enabled. The base kit (punches, kicks, aerial attacks, stomp, dive) stays available from the start and gains no code here.

## Ground rules for every PR

- **Gate:** every new rule runs only while its capability is held. Capabilities come only from `--carl-prog` pins and triggers, `--carl-dynamite`, `--carl-gauntlet` or a `carl_prog_*` fixture. With no flag, every existing golden is byte-identical: the 20 `EXPECTED_HASHES` (13 legacy, 2 DEATH-D, 5 llama), `GOLDEN_WALK_RIGHT_400`, the story hash, the party goldens, the 13 boss fixtures, the `q10_*` goldens, `demo01_*`, the CINE goldens, the whole-route autopilot hash, every `cf02_*`, `companion_*` and Engineer fixture, the ART-INT-02 anim traces and the PLAYTRACE goldens. `--carl-prog` alone on the opening route, DEMO-01 and the CF02 arena must also reproduce them. **No golden moves on purpose**; a PR that needs one to move stops and reports.
- **Data:** PR A lands the **complete** schema: `assets/data/gameplay/story_unlocks_v0.json` (capabilities with `hero`, `slot` and optional `requires`; triggers with a `grants` list; pins; notices; CP-Q44, so Donut's `jump_reach_boost` and `special_short_blink` from #175 are data rows only) and `assets/data/gameplay/carl_prog_v0.json` (every dynamite, interaction and gauntlet knob, names starting with the question ID, for example `cpq18_fuse_ticks`), loaded by `src/story_unlock.rs` and `src/carl_prog.rs`, validated and FNV-1a pinned like `companion_magic_v0.json`. A load error names the field. Later PRs only read values; a PR that must change one says so in its body.
- **IP-neutral contracts:** no engine type, event, field, cause or capability id says "dynamite", "gauntlet", "Carl", "Hoarder" or "Juicer". Names live in data display fields and in the fan-layer presentation only (DEATH-D rule).
- **Events and moves:** new `CombatEvent` variants (`CapabilityGranted`, `SpecialStarted`, `ChargeThrown`, `ChargeLanded`, `SpecialRejected`, `SpecialReady`) and the `MoveSpec` field `pierces_commit` are **appended** and mixed into the hash only when emitted or set. The ledger and the thrower hash nothing while empty or idle; the dynamite's charge slot mixes nothing while unused and its profile only when it is not the QA profile; a read-through capability (the biscuit) is never hashed or evented by the ledger (spec CP-Q31, CP-Q45).
- **Determinism:** no RNG anywhere in this work order. Squared-distance compares, exact tick compares, fixed index order.
- **Fixtures:** new ones live in `src/carl_prog_fixtures.rs` under the `carl_prog_*` namespace, with committed final hashes, replayed twice, headless and in the render loop. PR A adds the registry to `--list-fixtures` and one loop line to `scripts/ci_floor01_combat.sh`, so later PRs never edit the script.
- **CI gate (every PR, on the final head):** `cargo fmt --all -- --check`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked --all-targets`, `python3 scripts/check_docs.py`, `bash scripts/ci_floor01_combat.sh headless`, and the GitHub workflows `documentation`, `game`, `floor01-scene` green.
- **Review and merge:** an independent top-tier review per PR, then a fix check, then squash-merge by the orchestrator under the AGENTS.md delegation (speed mode). Gameplay is recorded as "merged, game-feel review pending". PRs do not edit `docs/04-production/backlog.md`; status goes in the PR body.
- **Model tiers:** all code, tests, evidence and docs: medium tier (Sonnet); top tier only if a medium-tier attempt fails or a design defect appears (it goes back to the spec, not decided in code). No new art in this work order; `burst_large` and the visible gauntlet are later art orders on the top-tier design, medium-tier execution, top-tier review route.
- **Locked files:** do not edit `src/prototype.rs`, `src/donut_mana.rs`, `src/party.rs`, `src/follower.rs`, `src/corridor.rs` or anything under `src/companion/` (owned by DONUT-MOBILITY-01 and COMPANION-AI-02). The biscuit stays where it is (CP-Q10).

- **COMPANION-AI-02 (#172):** **does** share files with this order: `src/bin/floor01_scene.rs` (its arg parse, which CP-A also edits), `src/playtrace/replay.rs` (CP-A's pin checks and replay-view mapping), `scripts/ci_floor01_combat.sh` (CP-A's one loop line) and `src/combat_anim/cf02.rs` (under CP-B2's `src/combat_anim/`).
