**Status:** design adopted (CF02-Q01..Q75, orchestrator under the owner's design-defaults directive, 2026-11-20; revision 2 adds CF02-G/H/I and the design-review fixes, revision 2.1 the re-review fixes); implementation not started. ## Ground rules for every PR

- **Gate:** every CF02 rule reads `cf02_rules` (default `false`) or its own knob, **including** the Q18 llama targets (switch `q18_llama_targets`, Q37) and the presentation overlays (death profile overlay, gore budget, cue overlay, acting overlays; Q36, Q69). With the switch off, every existing golden is byte-identical (20 `EXPECTED_HASHES` (13 legacy, 2 DEATH-D, 5 llama), `GOLDEN_WALK_RIGHT_400`, the story hash `931868d6afa56498`, 7 party, 13 boss and 8 `q10_*` goldens, `demo01_*`, the CINE goldens, and the whole-route autopilot hash `0363078d58558e95`), and `--demo` looks and sounds like the tested DEMO-01.
- **Data:** CF02-00 lands the **complete** knob schema (every Q01..Q75 value except the party knobs and the companion-profile values below) in `src/cf02.rs` and `assets/data/gameplay/cf02_combat_v0.json` (loaded, validated, FNV-1a pinned like `companion_magic_v0.json`); the party knobs are Q19 and Q20 only (`PartyTuning`, CF02-C2); Q13 becomes `UncontrolledHero::Companion(Cf02Assist)` (COMPANION-AI-01 01A-wire); Q14–Q17 and Q39 live in `assets/data/gameplay/companion_ai_v0.json` as profile `cf02_assist`, with knob names equal to the question IDs (`cf02_q14_swat_tell_tick`, ...), created by COMPANION-AI-01 01A-core (CF02-00 does not create the file); Q40 is the shared perception rule (`CompanionView`, [companion design section 17](../03-tech/companion-ai-command-system.md#17-reconciliation-with-combat-fun-02-and-autoplay-01)); the Q38 hold and the Q55 hop are move knobs in the json. Knob names equal the question IDs (for example `q02_stomp_startup`). Later PRs **read** values; a PR that must change one says so in its body and edits the file only while it holds the data token (see [shared files](#shared-files-and-who-owns-them-when)); otherwise it reports the change to the orchestrator. A load error names the field.
- **Events and moves:** new `CombatEvent` variants (`BodyContact`, `WallSlam`, `ShoreTripped`) and `MoveId` variants (`Stomp`, `FollowKick`, `AirKick`, `DiveStomp`) are **appended**, mixed into the hash only when emitted. Morale state enters the state hash only when `cf02_rules` is on. Fixed order on one tick: Carl, Donut, goblins, llamas (as today); morale is evaluated after the tick's combat events, in goblin index order.
- **Carl damage and the glance hook:** every Carl melee damage path that CF02-A/H/B add (FollowKick, Stomp, AirKick, DiveStomp) applies damage through `strike_group` or `strike_boss` with the `glance` argument, never a direct `take_hit`.
- **Determinism:** the only variety source is CF02-Q58's stateless hash of `seed`, `restarts`, goblin index and draw index. No wall clock, no unseeded RNG, no presentation RNG in simulation code.
- **Fixtures:** new ones use the `cf02_*` namespace in `src/cf02_fixtures.rs` (Donut and llama ones in `src/donut_fixtures.rs`), committed final hashes, replayed twice, headless and in the render loop. CF02-00 adds a `--list-fixtures <prefix>` enumeration over **every** registry, including `src/companion_fixtures.rs` (COMPANION-owned, empty after CF02-00; the `cf02_assist_*` fixtures live there, see [CF02-C2](#pr-sequence)), and `scripts/ci_floor01_combat.sh` loops over `--list-fixtures cf02_` and `--list-fixtures companion_`, so later PRs never edit it.
- **CI gate (every PR, on the final head):** `cargo fmt --all -- --check`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked --all-targets`, `python3 scripts/check_docs.py`, `bash scripts/ci_floor01_combat.sh headless`, and the GitHub workflows `documentation`, `game`, `floor01-scene` (plus `art-assets` for art PRs) green.
- **Review and merge:** an independent top-tier review per PR, then a fix check, then squash-merge by the orchestrator under the AGENTS.md delegation. Gameplay is recorded as "merged, game-feel review pending". The orchestrator updates the COMBAT-FUN-02 backlog row after each merge; PRs do not edit it.
- **Model tiers:** gameplay code and tests: medium tier (Sonnet); top tier only if a medium-tier attempt fails. Pixel art: one top-tier design pass for all CF02 poses (ACT-DESIGN), medium-tier execution per sheet, a separate top-tier review per sheet. Evidence, captures, checksums, README rows: medium tier.
- **Separate art sheets:** CF02 frames go into new sheets (`carl_h52_cf02`, `donut_h40_cf02`, `goblin_a_h36_cf02`, `goblin_b_h36_cf02` and a goblin slammed death sheet), never into the approved DEMO-01 sheets, so `--demo` art stays byte-identical.
- **AUTOPLAY-01 (#126, [spec](../03-tech/autoplay-01-automated-gameplay-evaluation.md)) alignment:** AUTOPLAY builds every `RawInput` as `RawInput { .., ..RawInput::NONE }` so CF02-A's new `down` field cannot break it; it plans an action-schema version (ActionV2) that adds the Down input after CF02-A, without which it cannot reach the stomp or the dive under `--cf02`; and it sets the temperament draw through the Q58 effective-seed override (`--cf02-seed`, or the same override on `CombatState`), starting each reset at `restarts` 0.
